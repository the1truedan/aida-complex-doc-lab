## Eventually: the control monorepo, scrubbed

When the whole project is ready for a **public fork of the control monorepo**, the intent is not a sterile showcase — it is to show **how the sausage was made**, minus what must stay private:

- **Remove:** PHI, medical bodies, private identifiers, credentials, and non-development personal chat tangents that are not load-bearing for the code intent  
- **Keep (selectively):** enough human context that the *why* is legible — caregiving pressure, rule-following and righteous indignation channeled into **legal, compliant, Socratic** search for solutions, and the hard work of packaging tools others can evaluate and improve  

Think of it as **personal CVE-style disclosure with a patch recommendation**: name the class of failure (document overload, agent context pit, cloud-token burn, accessibility false confidence), show the fix path, invite refinement — without dumping someone else’s chart.

The goal is **vulnerability that inspires**, not spectacle: people with *their* complex life contexts should feel licensed to **vibecode** from lived expertise into tangible programs that help in niches no generic demo would invent. This lab is an early public slice of that posture; the scrubbed monorepo fork is the later, fuller map.
